Challenge

The product had grown organically across 5 teams with inconsistent terminology, confusing UI labels, and no unified tone of voice. Users struggled with overlapping concepts—"Document," "File," "Asset," and "Item" were used interchangeably. This created friction in complex workflows and increased support burden.

Approach

1. User Research & Mental Models

Conducted 12 user interviews + analyzed support tickets to understand how users conceptualized core entities. Created mental model diagrams in FigJam showing user expectations vs. current taxonomy.

2. Taxonomy Development

Established a clear hierarchy: Workspace → Project → Document → Page/Section. Defined standardized terms for all UI elements, metadata, and error states.

3. Content Style Guide & Governance

Built a living style guide (Confluence) covering: tone of voice, microcopy patterns, error messaging frameworks, empty state language, and accessibility standards (WCAG 2.1 AA).

Deliverables

  • Interactive Taxonomy Guide in Figma showing terminology relationships and usage examples
  • Content Patterns Library with 340+ reusable snippets organized by context (onboarding, error recovery, guidance, etc.)
  • Microcopy Decision Tree for common UI elements (buttons, labels, help text)
  • Content Audit Report identifying 87 terminology conflicts and recommending fixes
  • Accessibility Checklist for content-related WCAG compliance

Impact

Support tickets related to terminology confusion dropped 23% within 3 months. New user onboarding improved by reducing cognitive load—users no longer needed to learn overlapping vocabularies. Design-to-development handoff time cut by 35% with clear, standardized language.

Project 2: Error Message & System Messaging Redesign

Role: UX Writer + Content Strategist | Timeline: 3 months | Context: Complex workflow automation feature

Challenge

Error messages were technical, vague, and unhelpful: "Invalid workflow state" or "Process 422: Conflict." Users couldn't understand what went wrong or how to fix it, leading to high support volume and frustration with the product.

Solution

Redesigned error, validation, warning, success, and empty state messaging using a human-centered framework:

Error Message Framework

❌ Before

Error 402: Field validation failed. Reference: wx7d9q

→ User confused, needs support

✓ After

Email address is invalid. Use a valid email format like name@company.com

→ User understands and self-resolves

Content Pattern Examples

Empty State (No permissions): "You don't have access to this workspace yet. Ask your admin to invite you or create a new workspace." Success Notification: "Workflow published! It's now live for all team members." Warning (Data at risk): "This change will affect 47 documents. You can undo for 30 days." In-App Guidance (Onboarding): "Add team members to collaborate in real time. You can manage permissions later."

Collaboration & Testing

  • Co-designed with UX Research team using error log analysis to prioritize high-impact messages
  • Conducted moderated usability testing (8 sessions) to validate message clarity and actionability
  • A/B tested 3 variations of recovery-focused messaging—measured task completion time and user confidence
  • Documented patterns in Figma component library for design system consistency

Project 3: Information Architecture & Navigation Redesign

Role: Content Strategist + IA Lead | Timeline: 4 months | Context: Reorganizing product navigation for 50+ features

36%
Time to feature reduced
12 → 5
Avg. clicks to goal
94%

Challenge

The navigation was feature-driven rather than user-goal-driven. Users couldn't find features, nested menus were 4 levels deep, and terminology didn't match user mental models (features were named after engineering concepts, not user tasks).

User-Centered IA Process

1. User Journey Mapping

Mapped 8 core user workflows in FigJam, identifying decision points and feature needs. Collaborated with Product and UX Research to validate assumptions.

2. Card Sorting Study

Conducted open and closed card sorts with 24 users to understand mental models. Used Optimal Workshop to analyze results and identify natural groupings.

3. IA Redesign & Taxonomy

Reorganized navigation from feature-based to goal-based structure. Relabeled sections to match user language. Reduced nesting from 4 levels to 2.

4. Label Testing

Tested 3 versions of navigation labels with unmoderated remote testing (45 users). Measured task completion, time-to-task, and confidence for each variant.

New Navigation Structure

Before (Feature-driven): Documents → Versioning & Collaboration Documents → Access Control & Permissions Documents → Content Processing Documents → Advanced Workflows After (Goal-driven): Documents ├─ Collaborate (co-edit, comments, version history) ├─ Share & Protect (permissions, access links) └─ Automate (workflows, processing, scheduling)

Ongoing Governance

  • Created IA governance doc in Confluence with clear guidelines for adding new features
  • Established quarterly navigation audits based on analytics heatmaps
  • Built content review process for navigation changes (UX Writer + Product Manager approval)

Project 4: Onboarding Content & Guided Experiences

Role: UX Writer + Content Designer | Timeline: 5 months | Context: Improving time-to-value for new users

44%
Day-1 activation improved
62%
Completion of core workflows
$287K
ARR impact (via churn reduction)

Challenge

First-time users were overwhelmed. 40% abandoned onboarding before completing the first workflow. Support team spent 60% of their time on basic "how do I..." questions.

Guided Onboarding Strategy

  • Progressive Disclosure: Revealed features gradually, inline with user tasks. Tooltips and helper text appeared contextually.
  • Conversational Tone: Reframed microcopy from instructional to conversational. "Create your first document" instead of "Initialize document entity."
  • Empty States as Teaching Moments: Used empty states to introduce features, not just announce emptiness.
  • Contextual Help: Created help content that lived next to the feature (not in separate docs) using in-app guidance popovers.

Content Examples

Onboarding Tooltip: "Invite your team to start collaborating. Everyone's edits appear in real time." Empty State (First upload): "No documents yet. Upload a PDF, Word doc, or image to get started. We'll extract the text automatically." Helper Text (Permissions field): "Can edit: Team members can create, modify, and delete documents. Can view: Team members can only read and comment."

Data-Driven Iteration

  • Tracked engagement with in-app guidance using analytics events (impression, interaction, dismissal)
  • Analyzed support tickets to identify which features caused confusion; prioritized content updates
  • Tested 2 variations of onboarding flow; measured completion rates, time-to-first-task, and user confidence surveys
  • Iterated on copy based on session recordings (watched 15 Clarity sessions to identify friction points)
